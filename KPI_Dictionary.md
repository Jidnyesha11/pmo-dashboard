# KPI Dictionary

| KPI                       | Definition / formula                                       | Unit / source                       | Frequency / owner           | Target / thresholds               | Interpretation and action                                                      |
| ------------------------- | ---------------------------------------------------------- | ----------------------------------- | --------------------------- | --------------------------------- | ------------------------------------------------------------------------------ |
| Lifecycle completion      | Mean of task completionPct                                 | % / tasks.csv                       | Weekly / PM                 | Plan-based                        | Use alongside milestones; not earned value.                                    |
| Schedule variance         | Forecast end minus baseline end for task                   | Days / tasks.csv                    | Weekly / PM                 | 0 days                            | Review dependencies and recovery options when positive.                        |
| Budget baseline           | Sum of approved category allocations                       | INR / project_config.json           | Monthly / PM + Finance      | ₹25,00,000                        | Baseline authority; contingency is included once.                              |
| Actual cost               | Sum actualCostINR through period                           | INR / costs.csv                     | Monthly / Finance           | Within approved budget            | Incurred cost only; commitments are separate.                                  |
| Budget variance           | Baseline − cumulative actual                               | INR / config + costs                | Monthly / Finance           | ≥ 0                               | Positive = under budget; negative = over budget.                               |
| Budget utilization        | Cumulative actual ÷ budget baseline                        | %                                   | Monthly / PM                | Forecast guided                   | High utilization before completion requires forecast review.                   |
| Sprint velocity           | Sum story points where status=Done, by sprint              | Story points / stories.csv          | Each sprint / Product Owner | Empirical trend                   | Use completed points only; never add hours.                                    |
| Sprint completion         | Completed points ÷ planned points                          | % / stories.csv                     | Each sprint / Scrum Master  | Team-set                          | Carryover requires refinement and replanning.                                  |
| Open risk count           | Risk status is not Closed                                  | Count / risks.csv                   | Weekly / PM                 | Track trend                       | Review owner, trigger, mitigation, due date.                                   |
| Critical risk count       | Score ≥16 (probability × impact)                           | Count / risks.csv                   | Weekly / PM                 | 0 preferred                       | Escalate response and contingency decision.                                    |
| Planned utilization       | Allocated hours ÷ available hours                          | % / team.csv                        | Weekly / resource lead      | 75–100% illustrative              | Above 100% is an over-allocation signal, not employee performance.             |
| Grounded answer rate      | groundedCount ÷ answeredCount                              | % / quality.csv                     | Evaluation run / AI lead    | Proposed ≥90%                     | Increase test coverage; review source and retrieval quality.                   |
| Unsupported answer rate   | unsupportedCount ÷ answeredCount                           | % / quality.csv                     | Evaluation run / AI lead    | Proposed ≤5%                      | Tune, constrain intents, or increase human fallback.                           |
| Human escalation rate     | humanEscalations ÷ sampleSize                              | % / quality.csv                     | Evaluation run / Product    | Proposed 15–35%                   | Interpret with accuracy and resolution; lower is not automatically better.     |
| Automated resolution rate | automatedResolutions ÷ sampleSize                          | % / quality.csv                     | Evaluation run / Product    | Proposed ≥55%                     | Check quality and reopen rate before increasing automation.                    |
| Retrieval relevance       | retrievalRelevantCount ÷ sampleSize                        | % / quality.csv                     | Evaluation run / AI lead    | Proposed ≥85%                     | Improve corpus, metadata, chunking or ranking.                                 |
| UAT pass rate             | uatPassed ÷ uatExecuted                                    | % / quality.csv                     | UAT cycle / Business owner  | Proposed ≥95%, no critical defect | Address blockers and repeat failed cases.                                      |
| AI response accuracy      | accurateAnswerCount ÷ answeredCount, based on human review | % / quality.csv                     | Evaluation run / AI lead    | Proposed ≥90%                     | Review rubric disagreements and failed intents; not a generic model benchmark. |
| Defect density            | defectCount ÷ executed UAT cases × 100                     | defects per 100 cases / quality.csv | Test cycle / QA lead        | Proposed declining                | Denominator is executed UAT cases in this simulation.                          |
| Reopened ticket rate      | reopenedTickets ÷ resolvedTickets                          | % / quality.csv                     | Monthly / Support lead      | Proposed <5%                      | Review resolution quality and policy.                                          |

AI measures are simulated test-set indicators, not model benchmarks. Targets above are proposed examples and are not achieved results.
